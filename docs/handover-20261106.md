## 1. 项目目标

### 1.1 一句话定位

> **一个通用粉末衍射全谱拟合（Rietveld）桌面软件**：输入任意 CIF + 任意 XRD 谱图，输出结构精修/谱图精修结果、R 因子、定量含量与可交付报告。

对标参照物是四款主流软件，但**只取其长、不学其繁**：

| 参照 | 学什么 | 不学什么 |
|---|---|---|
| GSAS-II | 能力完备度、序贯/多谱联合的思想 | 参数树式全参数暴露 |
| FullProf | 精修顺序的可操作性、TCH 峰形 | `.pcr` 文本配置的心智负担 |
| MAUD | 参数分组面板、**拟合质量**（当前对标主目标） | 需要研究者手工填 `.par` |
| Profex | 报告结构与 UI 简洁度 | — |

差异化定位：**易用性优先**——导航式「点一步、看一步」，而不是一屏几百个开关。

### 1.2 边界（做什么 / 不做什么）

| ✅ 本项目做 | ❌ 明确不做（归属） |
|---|---|
| Rietveld / Le Bail 全谱拟合 | 峰形处理、寻峰、单峰拟合（→ XinMatch） |
| 晶胞、原子坐标、B 因子、占位精修 | 物相定性鉴定、数据库检索（→ XinMatch / PolyXRD） |
| 零点/样品位移、背景、峰形、择优取向、微结构 | ab initio 结构求解（模拟退火/直接法） |
| 仪器辐射参数（λ、Kα1/α2 比）、QPA 定量 | 谱图格式转换（复用 Converter） |
| e.s.d.、相关性、R_Bragg、DW | 中子/TOF 数据（v1 明确延后） |
| CIF 写回、工程文件（.xinr）、报告导出、CLI/API | 多谱联合精修、硬约束框架（→ Pro 版） |

### 1.3 家族定位

```
PolyXRD（物相分析平台）
   └── XinMatch（峰形 + 物相分析，3.4.0）
          └── 导出 .xinm（谱图 CSV + COD CIF + manifest）
                 ↓ 导入
          XinRefinement（本项目：只做全谱拟合）
                 ↑ 复用
          家族已验证引擎（RutAna B 法 / NCA / NCM / LFP）
```

- 独立仓库、独立 GUI，但 core 层设计成**可被 import 的库**（`xinrefinement/api.py`，`API_VERSION` 做版本协商）。
- 未来 XinMatch 可直接 `import xinrefinement.core` 替代其 GSAS-II 委托。

### 1.4 「成功」的三层定义

这个项目的验收不是一句话，是三层递进的：

| 层 | 判据 | 现状 |
|---|---|---|
| **L1 数值可信** | 与家族已验证引擎**逐位一致**（浮点级），golden 冻结 | ✅ 达成（`tests/golden/method_b_roundtrip.json`，CLI Rwp = 3.409617019598457 逐位复现） |

## 2. 设计思路与设计方案

### 2.1 五条设计原则（先看这个，代码才看得懂）

| # | 原则 | 具体做法 | 为什么 |
|---|---|---|---|
| **D1** | **不重写数值核心** | 把家族已验证的精修引擎 vendor 进 `xinrefinement.core`，只做命名空间替换 + 通用化补丁 | 引擎在 TiO₂ 虚拟样 round-trip（Rwp 2.1–3.5%、回收误差 ≤0.09 pp）与 NCM811 实样上已验收；重写等于把所有坑重踩一遍 |
| **D2** | **先立基线再改** | P0 阶段就把 golden 冻结，之后每次改动都比对"逐位一致" | 没有基线就没有回归；"感觉变好了"不是证据 |
| **D3** | **声明式参数模型** | 用 `ParameterRegistry` 描述「有哪些参数、什么顺序、什么边界」，替换散落各处的 `_pack/_unpack/_bounds` | 一份描述同时驱动 pack/unpack/边界/GUI 分组/e.s.d./约束，避免五处手写五份不一致 |
| **D4** | **新能力一律 opt-in** | 新开关默认 `False`；要默认开必须拿出"全样零回归 + 实样有效"的证据 | 保证 golden 与既有调用零回归；默认值是产品承诺，不是实验田 |
| **D5** | **双轨过渡** | 新旧路径并存、逐位对拍，跑通了才切生产 | 出问题能一步回退，且回归测试本身就是对照实验 |

### 2.3 数值内核口径（必须懂，否则看不懂 Rwp 数字）

**变量投影（variable projection）两层结构**：

```
非线性层（LM / scipy-trf）：零点、U/V/W、η、asym、B_iso、PO r、织构 T(χ)、Popa LB、尺寸应变
        ↓ 给定非线性参数后
线性层（解析解 lstsq）：各相标度 scale + 背景系数（Chebyshev / tent / manual / interp）
        ↓
y_calc = Σ_相 scale_相 · Σ_峰 I_峰 · PV(2θ; 非线性参数) + background
```

- 线性层**每次非线性迭代都重解**，所以 scale 与背景永远是最优的——这是本项目比"全参数扔进 LM"稳的根本原因。
- 线性参数被消去后，非线性层的自由度少了一大截，LM 不容易发散。

**R 因子口径**（`core/refine/rfactors.py`）：

```python
rwp = 100 * sqrt(Σ w·(yobs-ycalc)² / Σ w·yobs²)      # include_bg=True（GSAS-II / MAUD 口径）
w   = 1/σ², σ 由 weight_mode 决定
```

| `weight_mode` | σ | 对应 |
|---|---|---|
| `sqrt`（默认） | `sqrt(max(y,1))` | **= MAUD `_pd_proc_ls_weight_scheme sqrt`** |
| `file` | 谱图文件自带 | 有实验 σ 的数据 |
| `unit` | 1 | 无权重 |
| `1/y` | `max(y,1)` | 老式 Poisson |
| `theoretical` | 由模型算 | GSAS-II 风格 |

> **口径对齐是 v1.5 的第一件事**（M1）。因为 MAUD 用 sqrt 实验权重 + 含背景 Rwp + 全谱，我们早期用 5–120° 裁剪 + tent 背景，直接比会**制造虚假差距**。

**峰形链**：`PV(U/V/W) → η 混合 → asym/tanθ 左右分裂 → Kα1/Kα2 双线 → 尺寸应变(X=4ε, Y=Kλ/D) → PO(March-Dollase r 或 EWIMV 19 点 ODF) → 逐相 ΔB_iso 高角衰减`

**背景模式**（`bg_mode`）：`cheb`（Chebyshev）/ `tent`（分片线性帽）/ `manual`（用户点）/ `interp`（**MAUD 式插值背景**：`interp_background_nodes()`，10 次迭代、2σ 带内避峰、取中位数）

### 2.4 参数模型：ParameterRegistry（整个项目的地基）

`core/params/registry.py` 用 `_Slot` 列表描述全部参数。**顺序是硬契约**，动了就破坏逐位一致性：

```
zero → U,V,W → eta → asym → bfactor
     → 每相 (fa,fc)
     → 每相 PO r（按相名排序）
     → 每相 Brindley μ·r
     → 每相织构 T(χ)（TEXTURE_N_GRID=19 维，按相名排序）
     → X → Y
     → [条件] 每相 aniso（6 size + 6 strain，仅 cfg.refine_aniso 且 prm.aniso）
     → [条件] 每相 B_iso（仅 cfg.refine_biso 且 prm.b_iso）
```

- P1.0b 落地时做过**双轨对拍**：17 组开关组合下 `pack/unpack/bounds` 与旧 `_pack` **逐位一致**（`tests/test_registry.py`）。
- 生产路径（P1.0c 起）`refine()` 的 `x0/bounds/unpack` 与残差热路径全走 registry；旧 `_pack/_unpack/_bounds` 保留为兼容 API + 回归参照，**不要删**。

> **坑预警**：registry 只在 `cfg.refine_aniso and prm.aniso` 同时为真时才生成 aniso 槽。**只打开开关不初始化 `prm.aniso`，等于没开，且不会报错**——这是 K17 的同族问题。

### 2.5 配方引擎：8 步与「可用 ≠ 默认执行」

`core/refine/recipe.py::DEFAULT_STEPS`（当前工作树顺序）：

| # | key | 中文 | 该步放开的自由度（严格按 `config_for()` 语义） |
|---|---|---|---|
| 1 | `zero` | 零点 / 样品漂移 | **仅** `zero`（+样品位移） |
| 2 | `bg` | 背景 + 峰形 | `zero` + `U/V/W`（背景系数由线性层每一步恒解，不在这张表里） |
| 3 | `scale` | 标度因子 | **仅** `zero`（scale 与背景是线性层解析解，恒参与） |
| 4 | `cell` | 晶胞参数 | 无 solve 自由度；由独立全晶胞引擎编排（`refine_cell` 刻意保持 `False`） |
| 5 | `profile` | 峰形参数 | `U/V/W` + `η` + `asym` |
| 6 | `xyz` | 原子坐标 | 无 solve 自由度；由独立站点引擎执行 |
| 7 | `micro` | 微结构 / 应力 / 择优取向 | `PO r` + `X/Y`（+ EWIMV 织构 / Popa LB，需显式开关） |
| 8 | `B` | 温度因子 | 每相 `ΔB_iso`（需 `refine_biso` 显式开启） |

三个关键设计语义：

1. **`available` ≠ 自动执行**。`xyz`/`B` 的 `available=True` 只表示"能力已落地、可以跑"，未显式开启时 `run_step` 记 `skipped`，**不做假执行**。
2. **`config_for()` 是唯一翻译层**。每一步只放开自己那组自由度，其余强制关；`cell` 步刻意保持 `refine_cell=False`（由独立引擎编排，否则两套机制抢同一组自由度）。
3. **每一步结束拍快照**（`StepRecord`），支持逐步回退；连跑可取消（`cancel_cb`）。

**步骤顺序曾经是个坑**：v1.4 出厂顺序是 `profile → xyz → B → micro`，B 抢在 micro 前面把高角失配吸收掉（ΔB_iso 撞 6 Å² 上界），导致 micro 只剩 1/3 收益。现已改为 `micro` 在 `B` 之前（未提交）。

## 3. 实现步骤的拆分原则与方法

> 这一节是给**能力较弱的执行模型**写的。核心思想：**把"判断"留在文档里，把"执行"拆到卡片里**。执行者不需要聪明，只需要不越界。

### 3.1 一张任务卡的合格标准（六个问题必须都有答案）

| # | 问题 | 不合格的表现 |
|---|---|---|
| Q1 | **目标**：这一步让什么可观测的量变好/变成什么？ | 「优化峰形模块」← 不可观测 |
| Q2 | **文件**：改哪个文件的哪个函数？ | 「改 core」← 无法定位 |
| Q3 | **签名**：新增/修改的函数签名、I-O 数据结构是什么？ | 留空 ← 执行者会自己发明接口 |
| Q4 | **算法要点**：公式/口径/边界条件写清楚了吗？ | 「按 Rietveld 标准做」← 歧义 |
| Q5 | **边界**：什么情况下跳过 / 回退 / 报错？ | 留空 ← 会静默产出错误结果 |
| Q6 | **验收命令 + 门限**：粘贴哪条命令、看到什么数字算过？ | 「跑测试通过」← 门限不明 |

### 3.2 卡片模板（照抄）

````markdown
### P?.? <编号> <一句话动作>

**目标**：<可观测量的变化；给数字门限>

**文件**
- `xinrefinement/core/xxx.py`：新增 `func_name(a: T, *, b: float = 1.0) -> R`
- `tests/test_xxx.py`：新增 N 项

**I-O**
- 入：<dataclass 字段、单位、缺省值>
- 出：<返回结构、失败时的表现（异常/None/降级字段）>

**算法要点**
- <公式；口径（2θ vs θ、含不含背景）；迭代次数；收敛判据>
- <与既有实现的数学关系：等价 / 超集 / 互斥>

**边界 / 护栏**
- <欠定 → 判 failed 并整体回退>
- <撞界 → 追加 warning，不静默>
- <缺前置数据（如 source_path 为 None）→ skipped，不做假执行>

**验收**
```bash
````

### 3.3 四条硬规则

| # | 规则 | 落地方式 | 违反的后果 |
|---|---|---|---|
| **R1** | **先冻结基线，再动代码** | P0 阶段把 golden 写进 `tests/golden/`，之后每张卡都验"逐位一致" | 没有基线，"改进"只能靠印象判断；收益与回归无法区分，出问题也无法二分 |
| **R2** | **新能力不得改默认路径** | 新引擎独立文件（`cell.py`/`site.py`）+ `RefineConfig` 新字段默认 `False` | 主路径一改，golden 全线漂移且定位成本极高 |
| **R3** | **每步必须有回退边界** | 双轨并存 / feature flag / 不改善就整体回退 | 真实案例：xyz 步在样 7 生成 48 个自由系数（欠定），无 `xyz_max_params=40` 护栏就会把结果做坏 |
| **R4** | **一步一个可观测数** | 每张卡提供一个数字：Rwp、参数回收误差、逐位 hash、耗时 | 「重构了参数模型」这类卡无法验收，也无法判断能不能合并 |

### 3.4 反面模式（不要这么拆）

| ❌ 反面模式 | 为什么错 | ✅ 正确拆法 |
|---|---|---|
| 把「能力落地」和「默认开启」合成一张卡 | 落地要验证正确性，默认开启要验证零回归 + 实样收益，两个判据完全不同 | 拆成两张：`#17a 实现 xyz 步（默认关）` + `#17b 评估 xyz 默认开启` |
| 一张卡同时改数值路径和 I/O | 出问题无法判断是算法错还是数据接错 | `cell.py` 独立引擎 + 单独接线卡 |
| 验收写「改进拟合质量」 | 无法判定完成 | 「样 1 Rwp 从 16.085 降到 ≤14.0，且 ΔB_iso 不撞 6 Å²」 |
| 让执行者自己"设计接口" | 弱模型会发明与 registry 不兼容的签名 | 文档里直接给出签名和 dataclass 字段 |
| 一步跨多个抽象层（core + GUI + CLI 同时改） | 改动面大、回归难定位 | 先 core（带单测）→ 再 CLI（带 CLI 测试）→ 最后 GUI（冒烟） |

### 3.5 弱模型友好写法（可直接照抄的骨架）

给执行者的 prompt 必须包含**五件事**，缺一件就会跑偏：

```
1. 绝对路径 + 函数名（不要写"精修引擎"，写 `xinrefinement/core/refine/site.py::refine_sites`）
2. 要求的行为 + 数值门限（"≤1e-3"、"逐位一致"、"必须 failed 而非抛异常"）
3. 禁止事项（"不要改 nonlinear.py 默认路径"、"不要新增默认 True 的开关"）
4. 验收命令（完整可粘贴，含 venv 路径与 --basetemp）
5. 输出格式（"改完贴出 pytest 汇总行 + git diff --stat"）
```

**反例 / 正例对照**：

| | 内容 |
|---|---|
| ❌ 弱 prompt | 「给精修引擎加上原子坐标精修，注意 Wyckoff 约束」 |
| ✅ 强 prompt | 「在 `core/refine/site.py` 实现 `refine_sites(model, inputs, *, max_iter=40, fixed_structures=()) -> SiteResult`。自由坐标维度用 (R−I) 零空间求（`symops.free_coordinate_basis`）。返回 `SiteResult(params, rwp, success, n_free, cell)`。自由系数 >40 直接返回 `success=False, n_free=48`（不要抛异常）。验收：`tests/test_site.py` 新增用例中 anatase Ti `n_free==0`、O `n_free==1`，坐标回收 <1e-3。」 |

### 3.6 真实示例：把「原子坐标精修」拆成 7 张卡（v1.4 #17）

这是本项目拆分粒度的**参照样本**：

| 序 | 卡片 | 可观测判据 |
|---|---|---|
| 1 | `CifStructure.source_path`：`parse_cif` 写入来源路径 | `parse_cif(path).source_path == path`；`parse_cif_string` 为 `None` |
| 2 | `cell.structure_with_cell` 元数据白名单补 `source_path` | 精修晶胞后 `source_path` 仍在（否则下一步找不到 CIF） |
| 3 | `site.refine_sites` 增 `fixed_structures` | 不参与结构精修的相作为常量基进线性层，强度不被算到被精修相标度上 |
| 4 | `site.refine_sites` 增 `bg_points` 透传 | 手动/插值背景固定层与主 solve 一致，否则坐标被背景差吸收 |

### 4.4 反过拟合验收（v1.5 起必须绑定）

对标 MAUD 最容易犯的错是**靠加自由度把 Rwp 刷下去**。所以每张"提升拟合质量"的卡，验收必须同时满足：

1. **Rwp 降了**；
2. **没有参数撞界**（ΔB_iso 不撞 6 Å²、PO r 不撞边界、织构 T(χ) 不贴 0 下界）；
3. **物理量落合理区间**（B 值同量级于 MAUD，晶胞与文献一致）；
4. **残差无系统结构**（不能是"背景被吞掉 + 弱峰消失"）。

> 实例：样 1 加 Popa LB 后 Rwp 16.085 → 12.596，同时 **ΔB_iso 撞 6 Å² 消失**——这才是健康信号（各向异性吸收了高角失配，B 不再背锅）。

### 4.6 验收不通过时的决策树

```
Rwp 变差？
├─ 逐位 golden 变了 → 停。这是回归，不是"改进"。回退，二分定位。
├─ golden 没变但实样变差 → 查口径（窗口/权重/背景/步骤顺序）是否与基线一致（K1/K19）
└─ 只有部分样变差

   ├─ 该样某步 failed（xyz 欠定 / LM 未收敛）→ 看 StepRecord.message
   └─ 该样基相模型有问题（如方石英）→ 单独专项（M8）
```

### 6.2 经验（L1–L8，方法论级）

| # | 经验 | 展开 |
|---|---|---|
| **L1** | **先口径，后算法** | 与外部软件对比前，必须把窗口/权重/Rwp 定义/背景扣除方式对齐。口径不一致会制造虚假差距，浪费的排查时间远超对齐成本 |
| **L2** | **一次只开一个自由度，看 Δ** | 多开同开会互相掩盖（K8）。每个能力单独测出边际收益，再决定组合顺序 |
| **L3** | **有护栏的能力才能默认开** | 没有护栏的自由度（ΔB_iso、xyz、19 维织构）默认关；有护栏（撞界告警、不改善回退、欠定判 failed）才考虑默认 |
| **L4** | **文档就是代码的一部分** | CHANGELOG 里专门有「设计口径（先说清楚，避免误用）」一节；评估报告按"关键发现 / 落地物 / 下一步"三段式。**口径写进文档，才不会在三个月后被自己误用** |
| **L5** | **数值回归用"逐位"** | 不是"误差 <1e-6"，是**逐位相等**。浮点行为一致才证明移植没走样；近似相等会把真实回归藏起来 |
| **L6** | **数据缺口要显式记录** | 样 5 的 10–100°、样 7 的方石英多型不确定、样 5 gehlenite 化学式与占位不一致——都写进报告，不"糊过去" |
| **L7** | **假设先验证再投入** | K20 花了半天验证一个错误假设。对照实验（单变量、同初值）成本远低于错误方向的实现成本 |
| **L8** | **能力落地 ≠ 默认开启** | 落地验证"正确性"，默认开启验证"零回归 + 实样收益"，两个判据、两张卡、两次评审 |
